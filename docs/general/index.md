# General

General 主线收录与模型家族和任务类型无关的 ablation 操作。这里的实现尽量只依赖张量语义，将“怎样从某个模型取到该张量”留给项目侧适配层。

## 通用边界

一个 General 方法应该：

- 接收明确的张量、维度约定和可选 mask，不在内部查找某个特定模型的层名。
- 区分计算与渲染：计算函数返回可保存、可比较的数值结果，渲染函数只负责生成图像。
- 不默认聚合 batch、head、token 或时间维；若需聚合，必须由调用方显式选择。
- 保留 dtype、device 和梯度语义，除非 API 文档明确声明会转换。
- 对形状、mask 和非有限值做早期检查，让迁移错误在小样本阶段暴露。

## 结果组织建议

不要只导出一张热力图。每个样本建议同时保留：

- 样本 ID、模型/权重标识、随机种子和实验组名称；
- 层、head、query/key token 的原始索引；
- 未归一化的计算结果与用于展示的归一化参数；
- 渲染图片及其色图、插值方式、透明度和目标分辨率；
- 与 baseline 相同口径的任务指标。

## 新方法的接入约定

新增方法时，同时提供最小数值示例、形状边界测试、一个可手算的基准例子和与本页结构一致的方法论说明。如果算法必须依赖模型内部实现，应将它放到 MLLM 或 Embodied 主线，而不是扩大 General 的责任。
